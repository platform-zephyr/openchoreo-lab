# Écarts entre les golden paths et le contrat v2alpha1

État relevé le 2026-11-17 sur `docs/schema/app.schema.json`, `tools/appgen/appgen.py` (en cours d'écriture par l'agent A2) et `tests/appgen/fixtures/platform/service-restricted.yaml`. Ce fichier **ne modifie pas** le schéma : il liste ce qui manque. Les corrections passent par une PR plateforme (classe protégée).

Légende de la colonne « Où » : **S** = schéma, **G** = générateur `tools/appgen`, **P** = objets `platform/` (CCT, CPT, CRT).

## Incohérences documentaires (hors schéma, pour le coordinateur)

- **Dossier de sortie.** `AGENTS.md` et `appgen` disent `generated/`, `APP-CONTRACT.md` §4 dit `gitops/`. Les golden paths suivent le code : `generated/`.
- **Commandes `appgen`.** APP-CONTRACT §4 décrit `appgen pin-resource <n> <env>` (lecture du cluster). Le code prend `pin-resource APP ENV RELEASE` : la release est lue par l'opérateur ou l'agent (`kubectl get resources.openchoreo.dev … status.latestRelease.name`, nom du champ [S]).
- **Nom de la ComponentRelease.** APP-CONTRACT annonce `<n>-<date>-<i>` (via `occ`). Le code produit `<n>-<hash10>` (hash du contenu, déterministe). Avantage pour le rollback : un `git revert` re-rend exactement l'ancien nom.
- **Label de composant.** `_checks` suppose `openchoreo.dev/component=<app>` sur Deployment, Service et Pod [S]. Le label de cellule `openchoreo.dev/project` + `openchoreo.dev/environment` est vérifié sur k3d (2026-11-17).
